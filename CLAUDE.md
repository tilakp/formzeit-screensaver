# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Formzeit is a native macOS `.saver` screensaver bundle written in Swift with **no Xcode project** — the whole toolchain is driven by hand from shell scripts using `swiftc`/`clang`/`codesign` directly. It ships four faces (Eclipse, Strata, Filament, and the original Braun BC12-inspired dial as "Classic"), a shared day/night color system, and a native settings sheet. `ScreenSaverView`'s `configureSheet` is a plain programmatic `NSWindow` (`Sources/ConfigureSheetController.swift`), not a `.xib`, which is what makes building without Xcode possible at all — keep any UI changes there programmatic too.

## Commands

- `./build.sh` — compiles `Sources/*.swift` with `swiftc -wmo`, links with `clang -bundle` into `Formzeit.saver/Contents/MacOS/Formzeit`, copies in `Info.plist`, and ad-hoc code-signs (`codesign --sign -`). Requires Xcode Command Line Tools (`swiftc`/`clang`), not a full Xcode install.
- `./build.sh -i` — same, plus installs to `~/Library/Screen Savers/Formzeit.saver` and kills `legacyScreenSaver`/`ScreenSaverEngine` host processes so the new build is actually picked up (macOS otherwise keeps the old bundle loaded in a long-lived host process even after the file on disk changes). System Settings caches its own preview and needs to be quit/reopened separately.
- `./preview.sh [seconds] [width] [height] [--preview|--config]` — the fast visual-iteration loop. Builds `TestHarness/main.swift` once (cached at `build/TestHarness`), which loads the *actual built* `Formzeit.saver` bundle via `Bundle(path:).load()` + `principalClass`, exactly like the real screensaver host, hosts it in an offscreen window, and renders a PNG to `screenshots/latest.png` (plus a timestamped copy). `--preview` renders the System Settings thumbnail mode (drift/orbit frozen); `--config` screenshots the settings sheet instead of the clock face. To preview a specific face/world/accent without going through the sheet: `defaults -currentHost write com.tilakpatel.formzeit face -string "eclipse"` (or `strata`/`filament`/`classic`), then `./preview.sh`. This writes to your real saved settings — restore or delete the key afterward (`defaults -currentHost delete com.tilakpatel.formzeit face`) rather than leaving your own settings changed.
- `./audit.sh` — a numerical audit, not a visual one. Compiles `Sources/*.swift` + `Audit/main.swift` and measures real pixels: Classic dial geometry (ring roundness, numeral-to-hour-ray centering, numeral-to-tick clearance — pinned to `face = classic` for the run) plus an informational Eclipse mean-frame-luminance sweep across the diel curve (§8-style budget: roughly ≤6% at night, ≤12% by day). It temporarily overwrites this machine's real `com.tilakpatel.formzeit` ScreenSaverDefaults domain to pin known settings, then restores whatever was there before (via a trap on EXIT) — don't strip that restore logic out. Run the geometry half after any change to `ClassicFace` layout; treat the luminance numbers as a budget check, not a pass/fail gate.
- There is no separate lint or unit-test command; `preview.sh` (visual), `audit.sh` (numeric), and the settings sheet's live preview together are the test suite for this project.

## Architecture

**Face dispatch**: `FormzeitRenderer` (`Sources/FormzeitRenderer.swift`) is a thin dispatcher, not a renderer — it switches on `defaults.face` and calls into one of four independent face implementations, each its own file: `ClassicFace.swift`, `EclipseFace.swift`, `StrataFace.swift`, `FilamentFace.swift`. Adding a fifth face means adding a file and a `FaceKind` case, not touching the others.

**Two-pass rendering per face, still driven by `FormzeitView`** (`Sources/FormzeitView.swift`): a cheap "cached" pass regenerated on a background queue every ~1.5s (`renderFace`) and an expensive-looking-but-actually-cheap "per frame" pass (`renderHands`), composited by swapping in a finished `CGImage` on the main thread rather than blocking it. What's cached differs by face — Classic caches the bezel/ticks/numerals (unchanged from v1); Eclipse caches *only* the field-light gradient, since the plate and every aperture cut through it must be redrawn every frame as the light source orbits; Strata/Filament have no cheap/expensive split of their own and just redraw whole every frame from the "per frame" hook. `FormzeitRenderer.render()` (both passes combined, no caching) exists for `TestHarness`/`Audit`/settings-sheet thumbnails, where a single deterministic frame is all that's needed.

**Color system** (`Sources/Palette.swift`, `Sources/Lighting.swift`): a `DielLighting` snapshot is computed once per frame for Eclipse/Strata/Filament from three layered decisions —
1. a 24-hour **diel curve** (`dielStops` in `Palette.swift`) giving a field/light/luminance triple per hour, interpolated in **Oklab** (`toOklab`/`fromOklab`/`mix`) rather than sRGB, specifically so a golden-hour-to-night midpoint stays chromatic instead of graying out;
2. a **world** (`ColorWorld`) that re-anchors the diel light/field hues toward its own colors at a fixed blend, preserving each stop's own lightness;
3. an **accent** (`Accent`) that either passes the diel light through unchanged (`.adaptive`, the default) or bends it toward a fixed hue.
`DielLighting` also owns the idle/burn-in dim ramp and the orbiting light source's phase (continuous absolute time, not elapsed-run-time, so the orbit doesn't reset to the same spot every relaunch). Classic does not use `DielLighting` for its own dial (unchanged v1 `ClassicFace.Lighting`, still night-window-based), but its second hand/hub color is resolved by `FormzeitRenderer` from the same `Accent`/`DielLighting` system, so Classic's accent quietly follows day/night color too.

**Elapsed time for any idle/burn-in ramp must come from `ProcessInfo.systemUptime` (monotonic), never `Date` subtraction** — a wall clock can step backward (NTP correction, sleep/wake drift, manual time change), which would snap dimming back to full brightness on something meant to run unattended for hours. Wall-clock `Date` is still correct and required separately for the diel/night-window lookup, which genuinely needs calendar time. This applies to both `ClassicFace.Lighting` and `DielLighting` — preserve the distinction if touching either.

**Eclipse's aperture model** (`Sources/EclipseFace.swift`, spec-driven): the plate is a single opaque disc; hands and hour marks are cut into it at one of four depths (score/shallow/deep/through) via `destinationOut` fills inside one `beginTransparencyLayer`/`endTransparencyLayer` pair, each depth group filled with the **default winding rule** (even-odd would double-punch the lens where hour and minute cuts overlap). A hand is a deep "body" capsule with a through-cut "core" running down it, built from the shared `capsule(_:_:_:_:_:_:_:)` path helper (`local(_:_:_:_:)` rotates lateral/outward coordinates by a clock angle, per §2.2's y-up convention). Through-cut cores are built around a `coreCenter` offset from true center — a parallax cue, always offset *away* from the current light source position. A `bevel` pass strokes every aperture's wall once per light source (clipped to the union of all cut paths), and a `corona` pass rims the plate edge with brightness scaled by angular proximity to each source. None of this animates directly — brightness at any point falls out of where the (continuously orbiting) light source currently sits.

**Settings**: `FormzeitDefaults` (`Sources/FormzeitDefaults.swift`) wraps `ScreenSaverDefaults(forModuleWithName:)`, exposes typed properties (`face`, `world`, `accentV2`, `movement`, `use24Hour`, `showNumerals`, `burnInProtection`, `nightDimming`), and posts `.formzeitSettingsChanged` on every write. `FormzeitView` and `ConfigureSheetController`'s live preview both observe that notification (plus `NSWorkspace.accessibilityDisplayOptionsDidChangeNotification`) and call `invalidateFaceCache()` to force an immediate cache regeneration rather than waiting out the normal refresh interval. A separate `FormzeitDefaults(transientFace:world:accent:)` initializer creates an ephemeral, throwaway `UserDefaults` domain (never touches the real saved settings) purely so the settings sheet's face-picker thumbnails can render each face with the real renderer at a fixed demo time.

**Settings-sheet layout gotcha**: the sheet's scroll content view (`ConfigureSheetController.FlippedView`) must override `isFlipped` to return `true` — a plain non-flipped `NSView` used as an `NSScrollView`'s document view opens scrolled to the *bottom* of its content, not the top, which silently "hid" the Face/World picker groups above the fold the first time this was built. Similarly, any custom borderless `NSButton` subclass added as an `NSStackView` arranged subview (the face/world/accent picker buttons) needs `translatesAutoresizingMaskIntoConstraints = false` plus an explicit `intrinsicContentSize` override (`RoundIconButton.setPreferredSize(_:)`) — relying on the `init(frame:)` frame alone collapses to zero size inside a stack view.

**Dial geometry constants are shared between drawing and the audit tool** — Classic's `tickOuterEdge`, `tickLength`, `tickWidth`, `numeralFontScale`, `numeralRingRadius` are `static`/non-private on `ClassicFace` specifically so `Audit/main.swift` can check against the same numbers the renderer actually uses, rather than duplicating hardcoded expectations that could silently drift out of sync.

**Numeral centering is intentionally non-obvious** — see the doc comment on `drawNumeral` in `ClassicFace.swift` before touching numeral layout. Numerals are centered on true glyph ink (via `CTLineGetBoundsWithOptions(.useGlyphPathBounds)`), not font line-height metrics, and positioned via `CTLineDraw` with an explicit baseline-relative `textPosition` (not `NSAttributedString.draw(at:)`, which uses a different coordinate origin and silently displaces glyphs). All twelve numerals are then vertically aligned on the font's cap-height midpoint (not each glyph's own ink midpoint) so old-style figures with descenders/ascenders (3, 5, 7, 9, 6, 8) still sit on one visual ring.

**Movement styles**: `Movement` enum lives in `Palette.swift` (cases `quartz`/`mechanical`/`digital`; `digital`'s rawValue is kept for persisted-defaults compatibility even though it now displays as "Sweep"). Classic keeps its original `exp·sin` quartz overshoot in `ClassicFace.secondsAngle`; Eclipse/Strata/Filament share a different damped-spring quartz implementation, `secondsAngleV2(_:_:)` in `EclipseFace.swift`.

## Files

- `Sources/FormzeitView.swift` — `ScreenSaverView` subclass, the bundle's `NSPrincipalClass`; owns the face-cache lifecycle, the animation loop, and settings/accessibility-change observers.
- `Sources/FormzeitRenderer.swift` — dispatches to the selected face; also owns wake-in progress and the live accessibility-flag reads (`reduceMotion()`/`increaseContrast()`).
- `Sources/ClassicFace.swift` — the original Braun BC12-inspired dial (v1 renderer, unchanged).
- `Sources/EclipseFace.swift` — the aperture/light-plate face, plus the shared `capsule`/`local`/`unitVector` geometry helpers and `secondsAngleV2`.
- `Sources/StrataFace.swift` — the three-arc gauge face.
- `Sources/FilamentFace.swift` — the sixty-filament face.
- `Sources/Lighting.swift` — `DielLighting` (per-frame color/luminance/orbit snapshot for the v2 faces) and the shared noise texture.
- `Sources/Palette.swift` — Oklab color math, the diel curve stops, `ColorWorld`, `Accent`, plus the legacy `AccentColor`/`Movement`/`FaceKind`/`DialPalette` types.
- `Sources/FormzeitDefaults.swift` — typed settings storage, including the transient-domain initializer used for settings-sheet thumbnails and the old→new accent migration.
- `Sources/ConfigureSheetController.swift` — programmatic settings-sheet UI: grouped containers, live preview, face/world/accent pickers.
- `TestHarness/main.swift` — standalone executable that loads the built `.saver` bundle like a real host and screenshots it (`preview.sh` driver).
- `Audit/main.swift` — standalone executable that renders a dial and asserts on measured pixel geometry, plus the Eclipse luminance sweep (`audit.sh` driver).
