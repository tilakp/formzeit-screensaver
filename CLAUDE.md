# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Formzeit is a native macOS `.saver` screensaver bundle written in Swift with **no Xcode project** — the whole toolchain is driven by hand from shell scripts using `swiftc`/`clang`/`codesign` directly. It ships five faces (Bauhaus — the default flat-colour plate — plus Classic, the original Braun BC12-inspired dial, and the light-based Eclipse, Strata and Filament), a shared day/night color system, and a native settings sheet. `ScreenSaverView`'s `configureSheet` is a plain programmatic `NSWindow` (`Sources/ConfigureSheetController.swift`), not a `.xib`, which is what makes building without Xcode possible at all — keep any UI changes there programmatic too.

## Commands

- `./build.sh` — compiles `Sources/*.swift` with `swiftc -wmo`, links with `clang -bundle` into `Formzeit.saver/Contents/MacOS/Formzeit`, copies in `Info.plist`, and ad-hoc code-signs (`codesign --sign -`). Requires Xcode Command Line Tools (`swiftc`/`clang`), not a full Xcode install.
- `./build.sh -i` — same, plus installs to `~/Library/Screen Savers/Formzeit.saver` and kills `legacyScreenSaver`/`ScreenSaverEngine` host processes so the new build is actually picked up (macOS otherwise keeps the old bundle loaded in a long-lived host process even after the file on disk changes). System Settings caches its own preview and needs to be quit/reopened separately.
- `./preview.sh [seconds] [width] [height] [--preview|--config]` — the fast visual-iteration loop. Builds `TestHarness/main.swift` once (cached at `build/TestHarness`), which loads the *actual built* `Formzeit.saver` bundle via `Bundle(path:).load()` + `principalClass`, exactly like the real screensaver host, hosts it in an offscreen window, and renders a PNG to `screenshots/latest.png` (plus a timestamped copy). `--preview` renders the System Settings thumbnail mode (drift/orbit frozen); `--config` screenshots the settings sheet instead of the clock face; `--layers` captures the CALayer tree rather than `drawRect`, which is the only way to check what actually renders on screen (see the two-layer note below). To preview a specific face/world/accent without going through the sheet: `defaults -currentHost write com.tilakpatel.formzeit face -string "eclipse"` (or `strata`/`filament`/`classic`), then `./preview.sh`. This writes to your real saved settings — restore or delete the key afterward (`defaults -currentHost delete com.tilakpatel.formzeit face`) rather than leaving your own settings changed.
- `./audit.sh` — a numerical audit, not a visual one. Compiles `Sources/*.swift` + `Audit/main.swift` and measures real pixels: Classic dial geometry (ring roundness, numeral-to-hour-ray centering, numeral-to-tick clearance — pinned to `face = classic` for the run) plus an informational Eclipse mean-frame-luminance sweep across the diel curve (§8-style budget: roughly ≤6% at night, ≤12% by day). It temporarily overwrites this machine's real `com.tilakpatel.formzeit` ScreenSaverDefaults domain to pin known settings, then restores whatever was there before (via a trap on EXIT) — don't strip that restore logic out. Run the geometry half after any change to `ClassicFace` layout; treat the luminance numbers as a budget check, not a pass/fail gate.
- There is no separate lint or unit-test command; `preview.sh` (visual), `audit.sh` (numeric), and the settings sheet's live preview together are the test suite for this project.

## Architecture

**Face dispatch**: `FormzeitRenderer` (`Sources/FormzeitRenderer.swift`) is a thin dispatcher, not a renderer — it switches on `defaults.face` and calls into one of five independent face implementations, each its own file: `BauhausFace.swift` (default), `ClassicFace.swift`, `EclipseFace.swift`, `StrataFace.swift`, `FilamentFace.swift`. Adding a sixth means adding a file and a `FaceKind` case, not touching the others.

**`BauhausFace` is the default and the one most likely to be edited** (`Sources/BauhausFace.swift`). It is a flat-colour plate built from two *opposed* depth cues, and reversing either is what makes it read as a diagram rather than an object:
- **Marks are recessed.** Numerals and the 60 markers get a pale rim offset toward the lower-right (away from the upper-left light) drawn *behind* the dark ink — see `deboss(...)`. Small and soft: too far or too opaque and it reads as misregistered two-colour printing.
- **Hands and hub are raised.** They cast down-and-right onto the plate, and their domed cross-section is bright on the side *facing* the light.

Four things in that file are easy to get wrong and are commented in place:
1. **CoreGraphics here is y-up**, unlike the y-down HTML canvas the design was prototyped in. Every direction constant (`LX`/`LY`, deboss offset, shadow offsets) is already converted; hands rotate by `-angle` to read clockwise from 12. Do not flip them again.
2. **`CTLineDraw` ignores the context fill colour** unless the attributed string carries `kCTForegroundColorFromContextAttributeName` (note: the Swift name ends `…AttributeName`). Without it the numerals draw black whatever colour is set, so the two-pass deboss silently has no effect on text.
3. **The hand outline is stroked *before* the fill, at double width.** The neck and paddle are two overlapping shapes; stroking after the fill leaves the paddle's round cap scarred across the neck as a visible arc.
4. **The diel luminance curve is deliberately NOT applied to this face** — see below.

**Two-pass rendering per face, still driven by `FormzeitView`** (`Sources/FormzeitView.swift`): a cheap "cached" pass regenerated on a background queue every ~6s (`renderFace`) and an expensive-looking-but-actually-cheap "per frame" pass (`renderHands`), composited by swapping in a finished `CGImage` on the main thread rather than blocking it.

**The two passes are two `CALayer`s, not two draws into `drawRect`** — `faceLayer` holds the cached bitmap as its `contents` (handed over once per regeneration), `handsLayer` sits above it and is redrawn per frame through a standalone `HandsLayerDelegate`. The delegate is deliberately *not* the view: AppKit's contract is that an `NSView` may only be the delegate of its own backing layer. Three consequences worth knowing before touching this file:
- `needsDisplay = true` is the wrong call now — use `setNeedsRedraw()`, which marks only the hands layer.
- The view's `layerContentsRedrawPolicy` is `.never`, and `draw(_:)` early-returns unless `NSGraphicsContext.current.isDrawingToScreen` is false. That path exists *only* for `cacheDisplay(in:to:)`, which walks drawRect and never sees sublayer contents — it is what keeps `preview.sh` and the settings sheet's snapshot working. If you ever remove the `isDrawingToScreen` guard, every on-screen frame renders both passes synchronously and the CPU regression is back.
- Because of that, a default `./preview.sh` screenshot does **not** exercise the layer path. `./preview.sh … --layers` captures via `layer.render(in:)` and does. What's cached differs by face — Classic caches the bezel/ticks/numerals (unchanged from v1); Eclipse caches *only* the field-light gradient, since the plate and every aperture cut through it must be redrawn every frame as the light source orbits; Strata/Filament have no cheap/expensive split of their own and just redraw whole every frame from the "per frame" hook. `FormzeitRenderer.render()` (both passes combined, no caching) exists for `TestHarness`/`Audit`/settings-sheet thumbnails, where a single deterministic frame is all that's needed.

**Color system** (`Sources/Palette.swift`, `Sources/Lighting.swift`): a `DielLighting` snapshot is computed once per frame for Eclipse/Strata/Filament from three layered decisions —
1. a 24-hour **diel curve** (`dielStops` in `Palette.swift`) giving a field/light/luminance triple per hour, interpolated in **Oklab** (`toOklab`/`fromOklab`/`mix`) rather than sRGB, specifically so a golden-hour-to-night midpoint stays chromatic instead of graying out;
2. a **world** (`ColorWorld`) that re-anchors the diel light/field hues toward its own colors at a fixed blend, preserving each stop's own lightness;
3. an **accent** (`Accent`) that either passes the diel light through unchanged (`.adaptive`, the default) or bends it toward a fixed hue.

**Why Bauhaus opts out of the diel curve.** On the light-based faces, dimming models less light reaching the viewer, which is physical and looks right. Bauhaus is a solid pastel plate, so multiplying it by a dim factor just mixes it toward black — Lagoon at 0.6 is grey-green mud, not a darker mint. Its `dimFactor` is therefore the burn-in idle ramp *only* (floored at 0.82), and day/night is handled by `activePalette` swapping to the chosen night plate between 22:00 and 07:00 when "Follow the day" is on. If you ever wire a brightness curve back into this face, look at it at 20:00 before believing it works.

**Bauhaus plates come in two lists**, `Palette.day` (eight) and `Palette.night` (Slate plus five lume); `Palette.all` is their union for `named(_:)` lookup, with Slate deduplicated because it appears in both. A lume plate sets `isLume`, which **inverts the face's depth model**: `deboss` stops drawing the pale down-right recess rim (on a dark plate that reads as printing misregistration, not as depth) and draws a symmetric halo of the mark's own colour instead, the hand's lume channel gets a glow and near-flat shading, and the hand's cast shadow is skipped entirely — a dark shadow on a near-black plate is invisible, and blur is the dominant per-frame cost. Measured at 5K: the glow adds ~3.8ms to the *cached* face pass (once per 6s), and the skipped shadows make the per-frame hands pass ~3ms **cheaper** than on a light plate.

Two things there are deliberate and easy to "fix" back into a problem: only the twelve hour markers glow (haloing all 60 would quadruple the blurred fills for marks a fifth the area), and the lume channel's shading is nearly flat (a charged lume pip is uniformly bright — shading it like a recess is what makes painted lume look painted on).

**Accent means two different things.** On Eclipse/Strata/Filament it tints the whole light. On Bauhaus and Classic it colours the *second hand only* — `BauhausFace.secondHandColor`, where `.adaptive` means "match the other two hands". The settings sheet rewrites the Accent caption per face for exactly this reason; keep that in sync if the semantics change again.
`DielLighting` also owns the idle/burn-in dim ramp and the orbiting light source's phase (continuous absolute time, not elapsed-run-time, so the orbit doesn't reset to the same spot every relaunch). Classic does not use `DielLighting` for its own dial (unchanged v1 `ClassicFace.Lighting`, still night-window-based), but its second hand/hub color is resolved by `FormzeitRenderer` from the same `Accent`/`DielLighting` system, so Classic's accent quietly follows day/night color too.

**Elapsed time for any idle/burn-in ramp must come from `ProcessInfo.systemUptime` (monotonic), never `Date` subtraction** — a wall clock can step backward (NTP correction, sleep/wake drift, manual time change), which would snap dimming back to full brightness on something meant to run unattended for hours. Wall-clock `Date` is still correct and required separately for the diel/night-window lookup, which genuinely needs calendar time. This applies to both `ClassicFace.Lighting` and `DielLighting` — preserve the distinction if touching either.

**Eclipse's aperture model** (`Sources/EclipseFace.swift`, spec-driven): the plate is a single opaque disc; hands and hour marks are cut into it at one of four depths (score/shallow/deep/through) via `destinationOut` fills inside one `beginTransparencyLayer`/`endTransparencyLayer` pair, each depth group filled with the **default winding rule** (even-odd would double-punch the lens where hour and minute cuts overlap). A hand is a deep "body" capsule with a through-cut "core" running down it, built from the shared `capsule(_:_:_:_:_:_:_:)` path helper (`local(_:_:_:_:)` rotates lateral/outward coordinates by a clock angle, per §2.2's y-up convention). Through-cut cores are built around a `coreCenter` offset from true center — a parallax cue, always offset *away* from the current light source position. A `bevel` pass strokes every aperture's wall once per light source (clipped to the union of all cut paths), and a `corona` pass rims the plate edge with brightness scaled by angular proximity to each source. None of this animates directly — brightness at any point falls out of where the (continuously orbiting) light source currently sits.

**Settings**: `FormzeitDefaults` (`Sources/FormzeitDefaults.swift`) wraps `ScreenSaverDefaults(forModuleWithName:)`, exposes typed properties (`face`, `bauhausPalette`, `bauhausNightPalette`, `world`, `accentV2`, `movement`, `use24Hour`, `showNumerals`, `burnInProtection`, `nightDimming`), and posts `.formzeitSettingsChanged` on every write. `FormzeitView` and `ConfigureSheetController`'s live preview both observe that notification (plus `NSWorkspace.accessibilityDisplayOptionsDidChangeNotification`) and call `invalidateFaceCache()` to force an immediate cache regeneration rather than waiting out the normal refresh interval. A separate `FormzeitDefaults(transientFace:world:accent:)` initializer creates an ephemeral, throwaway `UserDefaults` domain (never touches the real saved settings) purely so the settings sheet's face-picker thumbnails can render each face with the real renderer at a fixed demo time.

**The settings sheet hides controls that don't apply to the selected face** (`updateGroupVisibility()`): Plate is Bauhaus-only, World is for the light-based faces, Accent applies to all five (as light on three, as the second hand on Bauhaus/Classic), and "Show numerals" only applies to Eclipse/Filament. The night-plate row is hidden unless a swap can actually happen — "Follow the day" on *and* a light day plate — so `plateTapped` and `toggleFollowDay` both have to re-run `updateGroupVisibility()`. Adding a new colour control means adding it to that method too, or it will sit visible-but-inert on faces it does nothing for.

**Settings-sheet layout gotcha**: the sheet's scroll content view (`ConfigureSheetController.FlippedView`) must override `isFlipped` to return `true` — a plain non-flipped `NSView` used as an `NSScrollView`'s document view opens scrolled to the *bottom* of its content, not the top, which silently "hid" the Face/World picker groups above the fold the first time this was built. Similarly, any custom borderless `NSButton` subclass added as an `NSStackView` arranged subview (the face/world/accent picker buttons) needs `translatesAutoresizingMaskIntoConstraints = false` plus an explicit `intrinsicContentSize` override (`RoundIconButton.setPreferredSize(_:)`) — relying on the `init(frame:)` frame alone collapses to zero size inside a stack view.

**Dial geometry constants are shared between drawing and the audit tool** — Classic's `tickOuterEdge`, `tickLength`, `tickWidth`, `numeralFontScale`, `numeralRingRadius` are `static`/non-private on `ClassicFace` specifically so `Audit/main.swift` can check against the same numbers the renderer actually uses, rather than duplicating hardcoded expectations that could silently drift out of sync.

**Numeral centering is intentionally non-obvious** — see the doc comment on `drawNumeral` in `ClassicFace.swift` before touching numeral layout. Numerals are centered on true glyph ink (via `CTLineGetBoundsWithOptions(.useGlyphPathBounds)`), not font line-height metrics, and positioned via `CTLineDraw` with an explicit baseline-relative `textPosition` (not `NSAttributedString.draw(at:)`, which uses a different coordinate origin and silently displaces glyphs). All twelve numerals are then vertically aligned on the font's cap-height midpoint (not each glyph's own ink midpoint) so old-style figures with descenders/ascenders (3, 5, 7, 9, 6, 8) still sit on one visual ring.

**Movement styles**: `Movement` enum lives in `Palette.swift` (cases `quartz`/`mechanical`/`digital`; `digital`'s rawValue is kept for persisted-defaults compatibility even though it now displays as "Sweep"). Classic keeps its original `exp·sin` quartz overshoot in `ClassicFace.secondsAngle`; Eclipse/Strata/Filament share a different damped-spring quartz implementation, `secondsAngleV2(_:_:)` in `EclipseFace.swift`.

## Files

- `Sources/FormzeitView.swift` — `ScreenSaverView` subclass, the bundle's `NSPrincipalClass`; owns the face-cache lifecycle, the animation loop, and settings/accessibility-change observers.
- `Sources/FormzeitRenderer.swift` — dispatches to the selected face; also owns wake-in progress and the live accessibility-flag reads (`reduceMotion()`/`increaseContrast()`).
- `Sources/BauhausFace.swift` — the default flat-plate face: debossed marks, plaster grain, raised hands with a recessed lume channel, layered hub, and its own eight `Palette` plates.
- `Sources/ClassicFace.swift` — the original Braun BC12-inspired dial (v1 renderer, unchanged).
- `Sources/EclipseFace.swift` — the aperture/light-plate face, plus the shared `capsule`/`local`/`unitVector` geometry helpers and `secondsAngleV2`.
- `Sources/StrataFace.swift` — the three-arc gauge face.
- `Sources/FilamentFace.swift` — the sixty-filament face.
- `Sources/Lighting.swift` — `DielLighting` (per-frame color/luminance/orbit snapshot for the v2 faces) and the shared noise texture.
- `Sources/Palette.swift` — Oklab color math, the diel curve stops, `ColorWorld`, `Accent`, plus the legacy `AccentColor`/`Movement`/`FaceKind`/`DialPalette` types.
- `Sources/FormzeitDefaults.swift` — typed settings storage, including the transient-domain initializer used for settings-sheet thumbnails and the old→new accent migration.
- `Sources/ConfigureSheetController.swift` — programmatic settings-sheet UI: grouped containers, live preview, face/world/accent pickers.
- `TestHarness/main.swift` — standalone executable that loads the built `.saver` bundle like a real host and screenshots it (`preview.sh` driver).
- `Audit/main.swift` — standalone executable that renders a dial and asserts on measured pixel geometry, plus the Eclipse luminance sweep (`audit.sh` driver).
